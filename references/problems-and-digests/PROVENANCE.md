## Added later the same day

RFC 4648 was fetched on 2026-10-09, after the rest of this directory, when the design moved the S3 checksum decoding into a separate adapter package. That decoding needs the base64 alphabet and its padding and non-alphabet rules from their own source, rather than from RFC 9651, which only governs Structured Field Byte Sequences. Statements `RFC4648-3.2-1` through `RFC4648-4-3` were added to `statements.json` and checked the same way as the rest.

Four statements from the already-vendored `aws/api-API_HeadObject.md` were added on 2026-10-09, when the S3 adapter's mapping of `AskReceipt` to HeadObject needed text saying that HeadObject returns the CRC64NVME checksum, its type and the object's length: `S3API-HeadObject-request-header-ChecksumMode-2`, `S3API-HeadObject-response-header-ChecksumCRC64NVME-1`, `S3API-HeadObject-response-header-ChecksumType-1` and `S3API-HeadObject-response-header-ContentLength-1`. No file changed; the quotes are checked the same way as the rest.

## The NVMe excerpt

I fetched the full NVM Express NVM Command Set Specification, Revision 1.1 (PDF, sha256
`95782c03141ba277d76edfe187e32fc6911a086721c5a86f088827366bc562db`), but its legal notice only lets non-members review,
reference and cite it, and forbids derivatives. I didn't want to commit a redistributed copy, so
`crc/nvm-command-set-1.1-excerpt-5.3.1.3.txt` holds only the cited portion: the copyright citation line the notice asks for,
then section 5.3.1.3's opening paragraph, Figure 152's generator polynomial, and sections 5.3.1.3.4 and 5.3.1.3.5. These are
consecutive line ranges of `pdftotext -layout` output, copied as-is. Anyone who wants the whole document
can fetch the URL above and compare it against the PDF hash.

## What was fetched but deliberately not kept

- RFC 3230 and the legacy IANA "HTTP Digest Algorithm Values" registry. RFC 9530 obsoletes both, and the core
  shouldn't borrow vocabulary from a withdrawn spec.
- RFC 7807. RFC 9457 obsoletes it.
- RFC 9111. Nothing in scope depends on caching beyond the "MUST NOT be stored by a cache" lines already quoted from RFC 6585.
